simple-id 消息格式说明

## 核心规则

消息：单条消息可能由一个或多个segment组成。

### 全文格式

**分隔符**：多条消息之间用单独一行（即前后自带换行）的`---`分隔（规定：以在每条消息之后追加一行`---`的方式实现）。全文开头为单独一行的`---`
**消息末尾**: 每条消息末尾，'\n---\n'之前，再追加一个额外的'\n'
**时间戳**：所有消息之前插入一次时间戳，此后，连续消息间隔超过 3 分钟，插入`YYYY-MM-DD HH:MM`。时间戳使用与消息相同的分隔符规则，但不追加额外的换行符。

### 单条消息格式

以下格式描述中，大括号包裹的部分为当前部分描述，其余为需填充的字符串。

{@标记部分（可选）}[{发送者名称部分}]: {正文部分}

**发送者名称**：
普通用户：`名称(123456)`
机器人自己：`名称(me)(123456)`
昵称缺失时直接显示 `(ID)`，ID 缺失则 `unknown`
优先取群名片，没有则fallback到QQ昵称
**@标记**：某条消息中 `@` 了机器人时，为 `(有人@我)`，否则不包含@标记
**正文segment渲染**：
`text`：直接输出
`at`：输出 `@某人`
`image`：输出图片描述（由视觉llm处理）
`face`：`[face: 表情名]`
`record`：`[record: 语音]`
`video`：`[video: 文件名]`
`file`：`[file: 文件名]`
`json`：`[json: <原始JSON字符串>]`
`poke`：`[poke: type,id]`
`dice` / `rps`：`[dice: 结果]` / `[rps: 结果]`
`reply`（第一层）：换行并缩进两个空格的 `[ref 发送者(ID)]: 内容`，被引用的消息为**单条消息**，递归渲染仅渲染正文部分，末尾追加一个换行。
`reply`（嵌套 reply中的reply）：不换行的`[ref 发送者(ID)]`，不渲染内容。
`forward`：每条子消息换行并展开为缩进的 `[forward 发送者(ID)]: 内容`（每条子消息为**单条消息**，对每条子消息递归渲染，仅渲染正文部分。递归展开forward中的forward，每层缩进两个空格）；无内容时 fallback 为不换行的 `[forward:ID]`。forward中的reply可展开，且每层forward都刷新reply层数。reply缩进从父forward的缩进开始计算，再缩进两个空格。

## 数据结构设计

StoredMessage 包含时间戳、消息 ID、发送者 QQ、昵称、群名片、是否为机器人、是否 @ 机器人，以及正文段数组 segments。

StoredSegment 的类型包括 text、at、image、face、record、video、file、json、poke、dice、rps、reply、forward。其中：
- image 只存 sha256，description 由 images 独立表管理
- json 保存原始 JSON 字符串（QQ 小程序/卡片消息内容）
- face 的 id 为表情编号，NapCat 大表情会带 faceText（如 /汪汪）
- reply 含消息 ID，可递归嵌套解析后的完整消息
- forward 含转发 ID，可递归嵌套解析后的子消息列表

reply 与 forward 支持递归嵌套。未解析时保留 id，toString 阶段回退为 `[ref:reply-${id}]` / `[forward:${id}]`。

序列化 API：
- `singleMessageToString(msg)`：单条消息转文本
- `messagesToString(messages)`：消息数组转文本，自动处理时间戳与分隔符

toString 内部通过 RenderContext 控制缩进与嵌套状态：
- indent：2 空格缩进层级，用于 reply / forward 的换行展开
- replyDepth：reply 嵌套深度；0 表示第一层（换行展开），>0 表示嵌套（仅输出 `[ref 发送者(ID)]`）
- inForward：是否处于 forward 内部；每层 forward 重置 replyDepth 为 0
