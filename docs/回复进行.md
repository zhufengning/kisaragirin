# 回复进行

回复触发时，先获取该群所有消息，应用 Auto Compact 过滤后，将 compact 摘要消息 + 所有保留的原始消息一起发给 agent。

## 历史消息与本次消息

在数据库 kv_store 表中记录每个群最新的 `lastTriggerId`（messages 表中 id 是 autoIncrement 的）。该 id 前的消息视为历史消息，该 id 后的消息视为最新消息。重启后从 kv_store 恢复，不丢失上下文边界。

Auto Compact 会在消息过多时将旧消息摘要为 `special_type='compact'` 的消息。`buildPrompt` 获取消息时会先过滤掉已被 compact 的原始消息，只保留最新的 compact 消息及其之后的消息。

## 提示词结构

身份提示词（你是qq群中的bot...）-> 其他系统提示词 -> 人物设定 -> 历史消息开始提示 -> 历史消息 -> 最新消息开始提示 -> 最新消息 -> 开始回复提示词

最新消息和历史消息都采用simple-id消息格式全文版本。

## 回复过程

群聊中可能存在有技术含量的话题和没有技术含量的简单话题，因此允许agent先进行一轮回复，并判断是否需要进行深度研究，如果是，则需生成深度研究的关键词，交给深度研究agent。完成后，将该agent的结果发回回复agent，生成第二段回复。如果不需要深度研究，则进行第一轮回复后就可以退出了。

实现方式为交给回复agent一个reply_first_turn工具，包含三个参数：immediate_reply, action, deep_research_keyword

例如：
immediate_reply: "哈哈", action: FINISH
immediate_reply: "真有意思，让我研究研究", action: DEEP_RESEARCH, deep_research_keyword: "Java从入门到精通"

深度研究完后则给一个reply_second_turn工具，参数只需要包含最终回复。

如果agent没有产生期望的工具调用，应再进行一次输入提醒调用。

深度研究agent不由我们实现，它提供一个openai兼容的api。

需要添加ai.assignments.reply, ai.assignments.deep_research配置

## bot消息存储

每轮回复完成时，立刻将bot的新消息写入数据库。目前bot只回复纯文本消息。

## 并发控制

很有可能在本轮回复完成前，触发新回复，因此，我们需要确保单个群所有回复单线程进行，先进先出。每个群的agent相互隔离。
